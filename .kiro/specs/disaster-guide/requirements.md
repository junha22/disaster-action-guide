# 요구사항 — 위치와 상황에 맞는 재난 행동요령 안내 서비스

## 요약

- 학교가 확정한 20개 주제 중 선택한 주제: TOPIC 10 (의료·복지·안전) 위치와 상황에 맞는 재난 행동요령 안내 서비스
- 해결할 문제와 대상 사용자: 재난 행동요령은 공개돼 있지만 길고 일반적이다. 그래서 위급한 순간에 '내 상황'에서 먼저 할 일과 하면 안 되는 일을 골라내기 어렵다. 대상은 호우·태풍·산불에 대비하거나 그 상황에 놓인 시민이다. 특히 반지하 거주자, 운전자, 등산객, 고령자나 어린이와 함께 있는 사람을 돕는다.
- 행사 안에 완성할 핵심 기능(최대 3개):
  1. 상황 선택 → 맞춤 행동요령: 지금 할 일 TOP 3, 하면 안 되는 일, 항목별 공식 출처
  2. 가드레일을 적용한 AI 정렬: AI는 걸러진 공식 항목 안에서 순서를 정하고 한 줄 요약만 쓴다. 검증에 실패하거나 오류가 나면 기본 순서로 보여준다.
  3. 지역 대피시설 안내: 데모 지역의 대피시설 목록과 지도 링크
- 입력 데이터와 확보 방법(주최 측 제공 데이터 가정 금지):
  - 행동요령: 국민재난안전포털(행정안전부), 산림청, 지자체가 공개한 행동요령 페이지를 팀이 직접 읽고 항목 단위로 정리한다. 항목마다 출처 URL과 확인일을 적는다.
  - 대피시설: 공공데이터포털에 공개된 행정안전부 대피시설 데이터를 팀이 내려받아 데모 지역만 추린다. 내려받지 못하면 지자체 홈페이지의 공개 목록을 보고 3~5곳을 직접 입력한다.
  - 사용자 입력: 화면의 선택값과 선택 사항인 짧은 추가 설명.
  - 실시간 외부 API 없이 동작한다.
- 결과 화면과 정상 동작을 확인할 기준: 두 데모 시나리오가 서로 다른 TOP 3를 보여주고 모든 항목에 출처 링크가 있다. 로컬 mock 환경에서도 기본 순서로 끝까지 동작한다. 자세한 기준은 아래 요구사항별 수용 기준과 '시연 확인 기준'에 있다.
- 이번에 구현하지 않을 범위: 아래 '이번에 구현하지 않을 범위'에 있다.

**기록 저장: 사용하지 않는다.** 한 번 조회하고 끝나는 서비스다. 위치와 동반자 정보(건강·장애 여부 포함)를 서버에 남기지 않는 편이 안전하다. 공통 Record CRUD는 쓰지 않되 코드와 DB는 그대로 둔다. AI 호출 횟수는 공통 호출량 DB에 남는다.

## 용어

- **행동요령 항목**: 공식 자료에서 옮겨 정리한 한 문장 단위의 행동 지침. 고유 ID와 구분(할 일 / 하지 말 것), 출처를 가진다.
- **후보 항목**: 사용자가 고른 상황 조건으로 걸러낸 행동요령 항목.
- **기본 순서**: 데이터에 적어 둔 기본 우선순위로 후보를 정렬한 결과. AI 없이 만든다.
- **AI 정렬**: AI가 후보 ID 중에서 고른 TOP 3 순서. 검증을 통과했을 때만 쓴다.
- **금지 표현**: 재난별로 위험한 행동을 권하는 문구 목록(예: 엘리베이터 이용, 물이 흐르는 곳 건너기). 데이터 파일로 관리한다.

## 요구사항

### 요구사항 1. 상황 선택 입력

**사용자 스토리:** 재난 상황에 놓인 사용자로서 몇 번만 눌러 내 상황을 알리고 싶다. 긴 글을 쓸 여유가 없기 때문이다.

**수용 기준**

1. 화면은 다음 항목을 선택형으로 제공한다.
   - 재난 종류(필수): 호우, 태풍, 산불
   - 시점(필수): 대비, 발생 중, 이후
   - 지금 있는 곳(필수): 반지하 주택, 아파트·고층 건물, 단독주택, 차 안, 지하공간(지하주차장·지하차도·지하상가), 산·계곡, 하천·해안 주변, 그 밖의 실외
   - 함께 있는 사람(선택, 여러 개 가능): 어린이, 고령자, 거동이 불편한 사람, 반려동물
   - 지역(대피시설 안내용): 데모 지역 목록. 첫 번째 지역이 기본으로 선택된다.
2. 필수 항목 3개를 모두 고르기 전에는 결과 보기 버튼이 비활성 상태다.
3. 추가 상황 설명은 선택 입력이다. 200자를 넘게 입력할 수 없고 남은 글자 수를 보여준다.
4. 추가 설명 칸에 "이름·연락처·주소는 적지 마세요" 안내를 표시한다.
5. 결과는 결과 보기 버튼을 눌렀을 때만 요청한다. 선택을 바꿀 때마다 자동으로 요청하지 않는다.
6. 선택을 바꾸고 다시 결과 보기를 누르면 이전 결과를 지우고 새 결과를 보여준다.

### 요구사항 2. 맞춤 행동요령 결과

**사용자 스토리:** 사용자로서 내 상황에서 무엇을 먼저 하고 무엇을 절대 하면 안 되는지 한눈에 보고 싶다. 공식 근거도 바로 확인하고 싶다.

**수용 기준**

1. 시스템은 재난 종류와 시점이 일치하는 항목 중에서, 장소·동반자 조건이 사용자 선택과 일치하거나 조건이 없는(공통) 항목만 후보로 삼는다. 다른 재난의 항목은 결과에 나오지 않는다.
2. 결과 화면 맨 위에 "지금 할 일 TOP 3"를 번호와 함께 보여준다.
3. "하면 안 되는 일"은 TOP 3와 다른 색과 아이콘의 별도 영역에 기본 우선순위 순으로 보여준다. 처음에는 최대 3개를 보여주고 나머지는 펼쳐 볼 수 있다.
4. TOP 3에 들지 않은 할 일 후보는 "더 보기"에 기본 우선순위 순으로 보여준다.
5. 화면에 나오는 모든 항목은 출처 기관명과 원문 링크를 함께 보여준다.
6. 항목 문구는 데이터에 저장된 문구를 그대로 쓴다. AI가 항목 문구를 바꾸거나 새 항목을 만들지 않는다.
7. 장소·동반자 전용 항목이 없으면 공통 항목으로 결과를 채우고 "이 상황 전용 안내가 아직 없어 공통 안내를 보여줍니다"라고 표시한다.
8. 후보가 하나도 없으면 빈 화면 대신 국민재난안전포털 행동요령 링크와 안내 문구를 보여준다.

### 요구사항 3. AI 우선순위 정렬과 가드레일

**사용자 스토리:** 사용자로서 여러 조건이 겹친 내 상황에서 가장 급한 일이 맨 위에 오길 원한다. 동시에 AI가 지어낸 위험한 조언은 보고 싶지 않다.

**수용 기준**

1. 시스템은 서버에서 공통 AI 기능(backend/app/ai_service.py의 generate_text)으로 후보 항목(ID, 문구, 기본 우선순위)과 사용자 상황을 보낸다. 응답으로 TOP 3 ID와 60자 이내 한 줄 요약을 JSON으로 받는다. 브라우저는 Bedrock을 직접 호출하지 않는다.
2. AI에 보내는 후보는 15개 이하로 줄인다. 공통 제한인 입력 4000자, 지시문 300자, 출력 256토큰 안에 들어가야 한다.
3. AI 응답은 다음을 모두 만족할 때만 쓴다.
   - JSON으로 읽힌다.
   - TOP 3 ID가 모두 이번 후보의 '할 일' 항목에 있고 서로 중복되지 않는다.
   - 요약이 60자 이하이고 해당 재난의 금지 표현을 포함하지 않는다.
4. ID 검증에 실패하면 AI 결과 전체를 버리고 기본 순서를 보여준다.
5. ID 검증은 통과했지만 요약 검증에 실패하면 AI 정렬 순서는 쓰고 요약은 숨긴다.
6. AI 호출 한도 초과(429), Bedrock 오류(502), 입력 길이 초과(413), 시간 초과, 로컬 mock 응답일 때도 기본 순서로 결과를 끝까지 보여준다. 자동 재시도는 하지 않는다.
7. 결과 화면에 정렬 방식을 "AI 정렬" 또는 "기본 순서(AI 미사용)"로 표시한다. mock 응답을 AI 결과처럼 표시하지 않는다.
8. AI 요약에는 "AI 요약 · 참고용, 아래 공식 항목이 기준입니다" 표시를 붙인다.
9. 추가 상황 설명은 AI에 '사용자 메모'로만 전달한다. 메모에 "규칙을 무시해" 같은 지시가 있어도 위 검증은 그대로 적용된다.
10. 결과 보기 1회당 AI 호출은 최대 1회다.
11. 처리 중에는 로딩 상태를 보여주고 결과 보기 버튼을 다시 누를 수 없다.

### 요구사항 4. 대피시설 안내

**사용자 스토리:** 사용자로서 내 지역에서 갈 수 있는 대피시설과 가는 방법을 바로 보고 싶다.

**수용 기준**

1. 사용자가 고른 지역의 대피시설을 이름, 주소, 시설 종류와 함께 목록으로 보여준다.
2. 시설마다 지도 앱 링크를 둔다. 지도 SDK나 API 키 없이 열리는 외부 링크를 쓴다.
3. 데이터에 시설 종류가 여러 개 있으면, 고른 재난에 맞는 종류를 먼저 보여준다.
4. 목록 아래에 데이터 출처와 기준일을 표시하고 "실제 개방 여부는 지자체 안내를 확인하세요"라고 안내한다.
5. 고른 지역에 시설 데이터가 없으면 국민재난안전포털의 대피소 찾기 링크를 보여준다.

### 요구사항 5. 안전 고지와 119 안내

**사용자 스토리:** 사용자로서 정말 위급할 때는 앱이 아니라 119에 바로 연락해야 한다는 것을 놓치지 않고 싶다.

**수용 기준**

1. 모든 결과 화면에 "이 서비스는 실제 재난 발생 여부와 대피 명령을 판단하지 않습니다. 재난문자와 지자체·소방 안내를 먼저 따르세요."를 표시한다.
2. 119 전화 버튼(tel:119)을 결과 화면에서 항상 보이게 둔다. 이 서비스는 신고를 접수하거나 대신 전송하지 않는다.
3. 추가 설명에 위급 키워드(예: 갇혔, 고립, 다쳤, 의식, 물이 차, 불길)가 있으면 결과 맨 위에 119 연결을 강조한 배너를 띄운다. 이 판단은 키워드 목록으로 하며 AI에 맡기지 않는다.
4. 위급 배너가 떠도 행동요령 결과는 그대로 보여준다.

### 요구사항 6. 데이터 관리와 품질

**사용자 스토리:** 팀원으로서 행동요령과 대피시설 데이터를 근거가 분명한 형태로 관리하고 싶다. 그래야 AI가 없는 내용을 지어낼 여지가 없다.

**수용 기준**

1. 행동요령 항목은 다음 필드를 가진다: ID, 재난 종류, 시점, 장소 조건(없으면 공통), 동반자 조건(없으면 공통), 구분(할 일 / 하지 말 것), 기본 우선순위(1이 가장 급함), 문구, 출처 기관, 출처 URL, 확인일.
2. 문구는 원문의 뜻을 바꾸지 않는 범위에서 짧고 쉬운 말로 다듬는다. 원문에 없는 행동을 추가하지 않는다.
3. 재난 종류마다 공통 항목과 데모 시나리오에 필요한 항목을 포함해 15개 안팎을 정리한다.
4. 금지 표현 목록과 위급 키워드 목록을 데이터 파일로 둔다.
5. 데이터는 저장소의 정적 파일로 관리하고 서버 DB에 넣지 않는다.
6. 자동 테스트로 다음을 검사한다: 모든 항목에 출처 URL이 있다, ID가 중복되지 않는다, 필드 값이 허용된 선택지 안에 있다.

## 시연 확인 기준

- 시나리오 A: 호우 · 발생 중 · 반지하 주택 · 고령자 동반
- 시나리오 B: 산불 · 발생 중 · 산·계곡 · 동반자 없음
- 두 시나리오의 TOP 3가 서로 다르고, 화면의 모든 항목에 출처 링크가 있다.
- A의 "하면 안 되는 일"에는 침수·지하공간 관련 항목이, B에는 산불 관련 항목이 보인다.
- 로컬(mock): 두 시나리오 모두 "기본 순서(AI 미사용)"로 끝까지 표시된다.
- 서버(Bedrock): "AI 정렬"로 표시되고 TOP 3 ID가 모두 후보 안에 있다.
- 후보에 없는 ID나 금지 표현을 돌려주는 가짜 AI 응답을 넣으면 기본 순서로 표시되거나 요약이 숨겨진다(자동 테스트로 확인).
- 추가 설명에 "물이 차서 문이 안 열려요"를 넣으면 119 배너가 뜬다.

## 이번에 구현하지 않을 범위

- 주제 가이드의 제외 범위: 실제 재난상황 판정, 대피명령 발령, 긴급구조 접수
- 재난문자, 기상특보 같은 실시간 외부 API 연동
- 회원가입·로그인, 사용자 상황이나 결과 저장(공통 Record CRUD 미사용)
- 전국 대피시설 데이터. 데모 지역만 다룬다.
- 화면 안 지도 표시, GPS 기반 거리 계산
- 호우·태풍·산불 외 재난 유형(지진, 폭염 등)
- 자유 대화형 챗봇. AI는 정렬과 한 줄 요약만 맡는다.

## 핵심 기능 완료 후 선택 사항
