# 요구사항 — 호우 위험 구역을 피해 가는 안전 경로 안내 서비스

**한 줄 소개**: 비가 많이 올수록 지하차도, 침수 이력 도로, 하천변을 단계적으로 피해 가는 경로를 찾아 주고, 어떤 구역을 왜 피했는지 지도에 보여주는 광주 지역 경로 안내 웹 앱

## 요약

- 학교가 확정한 20개 주제 중 선택한 주제: TOPIC 10 (의료·복지·안전) 위치와 상황에 맞는 재난 행동요령 안내 서비스. 호우 행동요령 중 '지하차도·하천변 같은 위험한 곳을 피해 이동한다'를 실제 경로로 바꿔 안내하는 서비스로 해석한다.
- 해결할 문제와 대상 사용자: 집중호우 때 지하차도와 저지대 도로는 짧은 시간에 물에 잠긴다. 일반 내비는 교통 흐름으로 경로를 고르고 침수 위험은 반영하지 않는다. 운전자가 비가 얼마나 와야 어느 길이 위험한지 스스로 판단하기도 어렵다. 대상은 호우 때 광주 시내를 차로 이동하는 운전자다.
- 행사 안에 완성할 핵심 기능(최대 3개):
  1. 위험 회피 경로: 카카오 로컬 검색으로 출발지·목적지를 고르고, 기상청 강수 정보(또는 데모 슬라이더 값)에 맞춰 선택한 알고리즘으로 경로를 계산한다. 지도에 경로와 위험 구역을 그리고, 피한 구역과 늘어난 소요시간을 보여준다.
  - 내비 안내, 안내 중 자동 재탐색, 알고리즘 비교 패널, 평가 스크립트는 '핵심 기능 완료 후 선택 사항'에 둔다.
- 입력 데이터와 확보 방법(주최 측 제공 데이터 가정 금지):
  - 도로망: OpenStreetMap 데이터에서 광주광역시 범위를 잘라 Valhalla 경로 타일을 만든다.
  - 위험 구역: 팀이 침수흔적도, 침수피해지, 지하차도, 하천 공개 자료(공공데이터포털, 생활안전지도, 광주광역시 공개 자료)를 내려받아 data_pipeline으로 risk_zones.geojson을 만든다. 구역마다 출처와 확인일을 적는다. 내려받지 못한 유형은 공개 지도로 위치를 확인해 데모 구간 주변 구역을 직접 그린다.
  - 강수: 기상청 API(공공데이터포털)의 1시간 강수량과 호우 특보. 개발과 시연에는 데모 슬라이더 값으로 덮어쓴다.
  - 장소 검색: 카카오 로컬 API. 키가 없거나 호출에 실패하면 미리 정해 둔 광주 데모 지점 목록을 쓴다.
  - 사용자 입력: 검색어, 출발지·목적지 선택, 현재 위치(사용자가 버튼을 누른 경우만), 데모 모드 값, 알고리즘 이름.
- 결과 화면과 정상 동작을 확인할 기준: 같은 출발지·목적지에서 강수량을 올리면 tiered_rain 경로가 지하차도 → 침수 이력 → 하천변 순서로 더 많은 구역을 피한다. 단계마다 피한 구역과 baseline 대비 추가 소요시간이 표시된다. 기상청·카카오 API 키가 없어도 데모 슬라이더와 데모 지점으로 끝까지 동작한다. 자세한 기준은 아래 요구사항별 수용 기준과 '시연 확인 기준'에 있다.
- 이번에 구현하지 않을 범위: 아래 '이번에 구현하지 않을 범위'에 있다.

**기록 저장: 사용하지 않는다.** 경로는 요청할 때마다 계산하고 끝난다. 출발지·목적지 좌표와 검색어는 이동 경로를 드러내는 위치 정보이므로 서버 DB와 로그에 남기지 않는다. 공통 Record CRUD는 쓰지 않되 코드와 DB는 그대로 둔다.

**AI: 회피 경로 설명에만 쓴다(요구사항 8).** 경로 선택은 알고리즘만으로 한다. 알고리즘이 고른 경로의 이유를 LLM(Amazon Bedrock)이 두세 문장으로 설명한다. 공통 AI 코드(backend/app/ai_service.py)는 그대로 둔다.

## 용어

- **위험 구역**: 호우 때 물에 잠기거나 물이 불어날 수 있는 장소를 다각형으로 정의한 것. 유형은 지하차도, 침수 이력(침수흔적도·침수피해지), 하천변 세 가지다.
- **사용 중 구역**: 데이터에서 active가 true인 위험 구역. 데이터 오류나 공사 등으로 잠시 뺄 구역은 false로 둔다.
- **강수 단계**: 시간당 강수량으로 정한 0~3단계. 단계가 오를수록 피하는 구역 유형이 늘어난다(요구사항 4의 표).
- **반드시 피함 / 되도록 피함**: 강수 단계마다 피하는 유형을 두 가지로 나눈다. '반드시 피함' 유형의 구역을 지나는 경로는 고르지 않는다. '되도록 피함' 유형의 구역은 지날 수 있지만, 지날 때마다 우회 벌점(초)을 더해 그만큼 돌아가더라도 피하는 경로를 먼저 고른다.
- **일부 회피**: '반드시 피함' 구역은 모두 피했지만 '되도록 피함' 구역 일부를 지나는 경로. 지나는 구역과, 모두 피하는 경로와의 소요시간 차이를 함께 보여준다.
- **특보 단계**: 없음, 호우주의보, 호우경보.
- **기상 컨텍스트**: 경로 계산에 쓰는 시간당 강수량, 특보 단계, 기준 시각, 값의 출처(기상청 / 데모).
- **알고리즘(Strategy)**: 출발지·목적지와 컨텍스트를 받아 경로 계획을 돌려주는, 교체할 수 있는 경로 선택 방식.
- **경로 계획(RoutePlan)**: 알고리즘의 결과. 선택된 경로(route), 비교용 후보(alternatives), 회피 근거(explanation), 평가 지표(metrics)를 담는다.
- **OSRM 형식**: 경로를 담는 공통 JSON 형식. 모든 알고리즘과 엔진 어댑터가 이 형식으로 경로를 돌려준다.
- **엔진 어댑터**: 실제 경로 엔진(Valhalla 등)을 감싸 알고리즘이 엔진 종류와 상관없이 같은 방식으로 호출하게 하는 층.
- **위험 노출 점수**: 경로가 위험 구역 안을 지나는 거리(m)에 유형별 가중치를 곱해 더한 값. 0이면 위험 구역을 지나지 않는다.
- **baseline 경로**: 회피 없이 최단 시간으로 찾은 경로. 추가 소요시간과 위험 노출 감소를 계산하는 기준이다.

## 요구사항

### 요구사항 1. 출발지·목적지 지정 (카카오 로컬 검색)

**사용자 스토리:** 운전자로서 장소 이름이나 주소로 목적지를 찾고 싶다. 좌표를 찾거나 지도를 뒤질 여유가 없기 때문이다.

**수용 기준**

1. 사용자가 검색어를 입력하고 검색 버튼(또는 Enter)을 누르면 서버가 카카오 로컬 API(키워드 검색, 주소 검색)를 호출해 결과를 최대 10개 보여준다. 결과마다 장소 이름과 주소를 표시한다.
2. 글자를 입력할 때마다 자동으로 검색하지 않는다. 2글자 미만이면 요청하지 않는다.
3. 카카오 REST API 키는 서버 환경변수에만 둔다. 브라우저 코드, API 응답, 저장소에 키를 넣지 않는다.
4. 검색 범위는 광주광역시로 제한한다. 주소가 광주광역시가 아닌 결과는 "데모 지역 밖"으로 표시하고 고를 수 없다.
5. 출발지는 '현재 위치' 버튼이나 검색으로 정하고, 목적지는 검색으로 정한다. 위치 권한은 사용자가 '현재 위치'를 누를 때만 요청한다. 현재 위치가 광주광역시 밖이면 안내 문구를 보여주고 검색으로 정하게 한다.
6. 출발지와 목적지를 모두 정하기 전에는 경로 찾기 버튼이 비활성 상태다.
7. 카카오 키가 없거나 호출이 실패하면(오류, 시간 초과, 한도 초과) 안내 문구와 함께 데모 지점 목록(광주 안 5~8곳)에서 출발지·목적지를 고를 수 있다. 데모 지점은 정적 데이터 파일로 관리한다.
8. 카카오에는 검색어와 검색 범위만 보낸다. 사용자의 현재 위치는 보내지 않는다.

### 요구사항 2. 기상 컨텍스트 (기상청 API + 데모 슬라이더)

**사용자 스토리:** 운전자로서 지금 비가 얼마나 오는지에 맞춰 경로가 정해지길 원한다. 시연하는 팀원으로서는 실제로 비가 오지 않아도 강수량을 바꿔 가며 경로가 달라지는 것을 보여주고 싶다.

**수용 기준**

1. 서버는 기상청 API로 정해진 지점(수용 기준 8)의 시간당 강수량(mm)과 호우 특보 단계를 조회한다. 가까운 AWS 관측소의 최근 60분 누적 강수량을 먼저 쓰고, 쓸 수 없으면 초단기실황의 1시간 강수량을 쓴다. 기상청에는 좌표를 보내지 않는다(관측소 표는 전체를 받고, 초단기실황에는 5km 격자 번호만 보낸다).
2. 관측소 표는 서버에서 2분, 초단기실황은 격자와 지역별로 10분 동안 재사용한다. 그 안의 요청마다 기상청을 다시 호출하지 않는다. 초단기실황의 새 지점 조회는 분당 60회, 하루 5,000회까지만 하고, 넘으면 마지막 값을 쓰거나 가져오지 못했다고 표시한다. 기본 지역은 이 제한을 받지 않는다.
3. 화면에 시간당 강수량, 강수 단계, 특보 단계, 기준 시각, 출처("기상청")를 표시한다.
4. 데모 모드를 켜면 강수량 슬라이더(0~100mm, 5mm 단위)와 특보 선택(없음 / 호우주의보 / 호우경보)이 나타나고, 경로 계산에 기상청 값 대신 이 값을 쓴다. 데모 모드인 동안 화면과 경로 결과에 "데모 값 · 실제 기상 아님"을 표시한다.
5. 기상청 키가 없거나 조회에 실패하면 "기상 정보를 가져오지 못했습니다"를 표시하고 데모 모드로 바꾼다. 이때 경로 결과에 "실제 강수 미반영"을 표시한다.
6. 강수 단계를 나누는 기준(30 / 50 / 70mm)과 특보를 강수 단계에 반영하는 규칙은 strategies.yaml에서 관리한다. 특보 반영 규칙 초안: 호우주의보는 강수 단계를 최소 1, 호우경보는 최소 2로 올린다.
7. 경로 결과에는 계산에 쓴 기상 컨텍스트(강수량, 특보, 강수 단계, 출처, 기준 시각, 지역)를 함께 돌려준다.
8. 날씨 패널은 현재 위치 또는 광주·전남 안에서 고른 지역을 기준으로 보여준다. 기본값은 광주광역시다. 위치 권한은 사용자가 '현재 위치'를 고를 때만 요청하고, 이미 허용된 브라우저에서는 처음부터 현재 위치를 쓴다. 기본 화면의 현재 위치는 GPS 고정밀을 먼저 요청하고, 실패하면 Wi-Fi·기지국 위치를 쓴다. 오차가 크면 그 사실을 표시한다. 운행 화면은 시연 주행으로 둔다. 위치를 얻지 못하거나 광주·전남 밖이면 안내 문구를 보여주고 지금 지역을 유지한다.
9. 실제 기상으로 경로를 계산할 때는 패널 지역이 아니라 출발지의 날씨를 쓴다. 운행 중 재확인(요구사항 9)은 차 위치의 날씨를 쓴다. 다른 곳의 비가 이 경로를 정하면 안 되기 때문이다. 패널과 강수 단계가 다르면 패널에 그 사실을 표시한다. 전남을 고르면 경로 규칙에 쓰지 않고 지도 강조도 바꾸지 않으며, 경로 안내가 광주 안에서만 된다고 표시한다.
10. 특보는 지점이 속한 시군의 특보구역 코드로 거른다. 세분된 시군은 어느 쪽 구역이든 특보가 있으면 그 시군의 특보로 본다.

### 요구사항 3. 위험 구역 데이터와 지도 레이어

**사용자 스토리:** 운전자로서 어디가 위험한 곳인지 지도에서 보고 싶다. 팀원으로서는 위험 구역을 근거가 분명한 데이터로 관리하고 싶다.

**수용 기준**

1. 위험 구역은 저장소의 정적 GeoJSON 파일(risk_zones.geojson)로 관리하고 서버 DB에 넣지 않는다. 각 구역은 다각형(Polygon 또는 MultiPolygon)이며 다음 속성을 가진다: ID, 이름, 유형(지하차도 / 침수 이력 / 하천변), 사용 여부(active), 원본 자료 이름, 출처 URL, 확인일.
2. data_pipeline 스크립트가 원본 자료(침수흔적도, 침수피해지, 지하차도, 하천)를 읽어 risk_zones.geojson을 만든다. 점이나 선으로 된 원본(지하차도 위치, 하천 중심선)은 파이프라인 설정의 기본 반경만큼 넓혀 다각형으로 바꾼다. 같은 입력이면 같은 결과를 만든다.
3. 경로 계산 때는 strategies.yaml의 유형별 버퍼 반경만큼 구역을 더 넓혀 여유를 두고 피한다.
4. 위험 구역은 공개 자료로 만든 실제 구역만 둔다. 실제 자료가 없는 유형(현재 지하차도·하천변)은 구역 없이 둔다. 직접 그린 더미 구역은 2026-10-30에 제거했다.
5. 서버는 위험 구역 목록 API를 제공하고, 화면은 이 API로 지도 레이어를 그린다.
6. 지도에 위험 구역을 유형별 색으로 그리고 범례를 둔다. 현재 강수 단계에서 피하는 구역은 진하게, 피하지 않는 구역은 흐리게 그린다.
7. 구역을 누르면 이름, 유형, 출처, 확인일을 보여준다.
8. 자동 테스트로 다음을 검사한다: ID가 중복되지 않는다, 도형이 유효한 다각형이다, 좌표가 광주광역시 범위 안에 있다, 유형이 허용된 값이다, 모든 구역에 출처와 확인일이 있다.

### 요구사항 4. 교체할 수 있는 경로 알고리즘

**사용자 스토리:** 팀원으로서 화면 코드를 건드리지 않고 경로 알고리즘을 바꾸거나 새로 추가하고 싶다. 어떤 방식이 위험을 덜 지나면서 시간을 덜 늘리는지 실험해야 하기 때문이다.

**수용 기준**

1. 모든 알고리즘은 같은 인터페이스를 따른다. 출발지·목적지 요청과 컨텍스트(기상 컨텍스트, 위험 구역 레이어, 엔진 어댑터, 파라미터)를 받아 경로 계획(route, alternatives, explanation, metrics)을 돌려준다.
   - explanation: 피한 위험 구역 목록, baseline 대비 추가 소요시간과 추가 거리, 회피 실패 시 그 이유
   - metrics: 위험 노출 점수(선택 경로와 baseline), 총 거리, 예상 소요시간
2. route와 alternatives는 OSRM 형식이다. 알고리즘이 달라도 응답 형식은 같다. 화면은 경로가 어떤 알고리즘으로 만들어졌는지 몰라도 그릴 수 있다.
3. 새 알고리즘은 strategies/ 폴더에 파일 하나를 추가하고 @register("이름")을 붙이면 등록된다. API나 화면 코드를 고치지 않아도 알고리즘 목록 API와 경로 API에서 쓸 수 있다.
4. 기본으로 다음 4개를 제공한다.

| 이름 | 방식 | 용도 |
| --- | --- | --- |
| baseline | 회피 없이 최단 시간 | 비교 기준 |
| hard_exclude | 사용 중 구역을 강수량과 관계없이 모두 제외 | 가장 단순한 회피 |
| tiered_rain | 강수 단계에 따라 제외할 구역 유형을 늘림 (아래 표) | 메인 알고리즘, 화면 기본값 |
| rerank | 후보 경로 여러 개를 만들고 점수(소요시간 + λ × 위험 노출)가 가장 작은 경로를 고름 | 가중치 실험 |

5. tiered_rain은 강수 단계에 따라 다음 유형의 사용 중 구역을 피한다.

| 시간당 강수량 | 강수 단계 | 반드시 피함 | 되도록 피함 |
| --- | --- | --- | --- |
| 30mm 미만 | 0 | 없음 (baseline과 같은 경로) | 없음 |
| 30mm 이상 | 1 | 지하차도 | 침수 이력(우선 회피) |
| 50mm 이상 | 2 | 지하차도, 침수 이력(우선 회피) | 침수 이력(일반, 주변보다 높은 편) |
| 70mm 이상 | 3 | 지하차도, 침수 이력 전체, 하천변 | 없음 |

   하천변은 자료가 없어 지금은 효과가 없다. 화면은 구역 자료가 있는 유형만 범례와 안내 문구에 보여주고, 자료가 생기면 설정 변경 없이 나타난다.

   - 엔진 호출 결과(제외 반복의 매 회차 경로와 엔진 대안 경로)를 모두 후보로 모은다. '반드시 피함' 구역을 지나는 후보는 버리고, 남은 후보 중 비용(소요시간(초) + '되도록 피함' 구역마다 진입 벌점 + 통과 길이 × m당 벌점)이 가장 작은 경로를 고른다.
   - 고른 경로가 '되도록 피함' 구역을 지나면 '일부 회피'로 표시하고, 지나는 구역 목록과 모두 피하는 후보와의 소요시간 차이(없으면 "모두 피하는 경로를 찾지 못했습니다")를 보여준다. 일부 회피 경로를 안전한 경로처럼 표시하지 않는다.

6. rerank는 엔진의 대안 경로와 구역 제외 조합(제외 반복의 매 회차 경로 포함)으로 후보를 여러 개 만들고, 점수(소요시간(초) + λ × 위험 노출 점수)가 가장 작은 후보를 고른다. 나머지 후보는 alternatives에 담는다.
7. 파라미터(λ, 유형별 버퍼 반경, 강수 단계 기준, 단계별 반드시 피함·되도록 피함 유형, 유형별 진입 벌점과 m당 벌점, 특보 반영 규칙, 유형별 위험 가중치)는 strategies.yaml에 둔다. 경로 요청에서 덮어쓸 수 있고, 허용되지 않은 키나 범위를 벗어난 값이면 422 오류를 돌려준다.
8. 사용자 화면은 tiered_rain만 쓰고 알고리즘을 고르는 화면은 두지 않는다. 다른 알고리즘은 API의 strategy 값으로 비교할 수 있다.
9. '반드시 피함' 구역을 모두 피하는 경로가 없으면(제외 후 도착 불가, 출발지나 목적지가 위험 구역 안에 있음 등) 후보 중 '반드시 피함' 구역을 가장 적게 지나는 경로를 돌려준다. 이때 "위험 구역을 피하는 경로를 찾지 못했습니다" 경고, 그 이유, 경로가 지나는 위험 구역 목록, baseline 대비 줄어든 구역 수와 추가 시간을 함께 표시한다. 회피하지 못한 경로를 안전한 경로처럼 표시하지 않는다.
10. 같은 입력(출발지·목적지, 기상 컨텍스트, 파라미터)이면 같은 경로 계획을 돌려준다.
11. 자동 테스트로 다음을 검사한다: 가짜 엔진 어댑터로 4개 알고리즘이 모두 같은 형식을 돌려준다, tiered_rain이 단계 경계값(29/30, 49/50, 69/70mm)에서 맞는 유형을 제외한다, '반드시 피함' 구역을 지나는 후보는 고르지 않고 '되도록 피함' 구역은 벌점과 우회 시간을 비교해 고르며 일부 회피를 표시한다, 회차 중간에 나온 후보도 버리지 않는다, 특보 반영 규칙이 맞게 적용된다, 잘못된 파라미터 덮어쓰기와 등록되지 않은 알고리즘 이름을 거부한다, 회피 불가 상황에서 경고와 함께 '반드시 피함' 구역을 가장 적게 지나는 경로를 돌려준다.

### 요구사항 5. 경로 엔진 어댑터 (Valhalla)

**사용자 스토리:** 팀원으로서 경로 엔진을 바꿔도 알고리즘과 화면을 다시 만들고 싶지 않다.

**수용 기준**

1. 알고리즘은 엔진 어댑터를 통해서만 경로 엔진을 호출한다. 어댑터는 출발지, 목적지, 제외할 다각형 목록, 대안 경로 개수를 받아 OSRM 형식 경로를 돌려준다.
2. 기본 어댑터는 Valhalla다. Valhalla Python 바인딩(pyvalhalla)으로 서버 프로세스 안에서 실행하며, Docker나 별도 엔진 서버를 쓰지 않는다. 광주광역시 OSM 데이터로 만든 타일을 쓰고, 제외할 구역은 Valhalla의 exclude_polygons로 넘긴다.
3. 자동차 경로만 계산한다.
4. 엔진을 불러올 수 없거나(타일 없음 등) 시간 초과(초안 10초)면 경로 API는 오류 코드와 "경로 엔진에 연결할 수 없습니다"를 돌려주고 화면은 이 문구를 보여준다. 자동 재시도는 하지 않는다.
5. 제외 다각형이 엔진 제한을 넘어 엔진이 요청을 거부하면 요구사항 4의 9처럼 회피 실패로 처리한다.
6. 타일 경로와 시간 제한은 환경변수나 설정 파일로 바꿀 수 있다.
7. 자동 테스트는 실제 엔진 없이 가짜 어댑터로 돌아간다.

### 요구사항 6. 경로 결과 화면과 회피 근거

**사용자 스토리:** 운전자로서 이 경로가 어떤 위험을 피했고 그 대신 시간이 얼마나 늘었는지 한눈에 보고 싶다.

**수용 기준**

1. MapLibre 지도에 선택된 경로, 출발지·목적지, 위험 구역 레이어를 그린다. 배경 타일은 키 없이 쓰는 OpenFreeMap을 쓰고 지도 출처 표기를 유지한다. 경로 전체가 보이도록 지도 범위를 맞춘다.
2. baseline 경로를 다른 색의 점선으로 함께 그린다. 사용자가 끄고 켤 수 있다.
3. 경로 요약에 총 거리, 예상 소요시간, 적용 알고리즘, 강수 단계와 값의 출처(기상청 / 데모)를 표시한다.
4. 회피 근거에 피한 위험 구역 목록(이름, 유형), baseline 대비 추가 소요시간과 추가 거리, 위험 노출 점수(baseline → 선택 경로)를 표시한다.
5. 강수 단계가 0이면 "현재 강수 단계에서는 피하는 구역이 없습니다"를, baseline 경로가 피해야 할 구역을 지나지 않으면 "이 경로에는 지금 피해야 할 구역이 없습니다"를 표시한다.
6. 경로는 경로 찾기 버튼을 눌렀을 때 계산한다. 결과가 표시된 상태에서 데모 슬라이더나 특보 선택을 바꿔 강수 단계가 달라지면 경로를 1회 다시 계산한다. 단계가 같으면 다시 계산하지 않는다.
7. 계산 중에는 로딩 상태를 보여주고 경로 찾기 버튼을 다시 누를 수 없다.
8. 새로 계산하면 이전 경로와 회피 근거를 지우고 새 결과를 보여준다.

### 요구사항 7. 안전 고지와 위치 정보 처리

**사용자 스토리:** 사용자로서 이 앱이 알려주지 못하는 것이 무엇인지 알고 싶고, 내 이동 경로가 어딘가에 남지 않길 바란다.

**수용 기준**

1. 경로 결과 화면에 "이 서비스는 실제 도로 통제와 침수 여부를 확인하지 않습니다. 지하차도 통제, 재난문자, 경찰·지자체 안내를 먼저 따르세요."를 항상 표시한다.
2. 실시간 교통을 반영하지 않는다는 점과 위험 구역 데이터 기준일을 표시한다.
3. 검색어와 출발지·목적지 좌표는 POST 본문으로 보낸다. URL 쿼리에 넣지 않아 서버 접근 로그에 남지 않게 한다.
4. 서버는 좌표, 검색어, 경로를 DB나 파일에 저장하지 않고 오류 로그에도 남기지 않는다.
5. 서버에서 밖으로 나가는 정보는 카카오에 보내는 검색어와 검색 범위, 기상청에 보내는 5km 격자 번호(현재 위치를 쓰면 대략적인 위치가 드러난다), Bedrock에 보내는 경로 설명용 사실(강수 단계, 소요시간(분), 지나는 위험 구역의 이름·유형·근거·길이)뿐이다. Bedrock에는 좌표와 검색어를 보내지 않는다. 경로 계산(Valhalla)은 서버 안에서 끝난다. 브라우저는 지도를 그리려고 OpenFreeMap에 타일을 요청하므로, 보고 있는 지도 범위는 OpenFreeMap에 드러난다.
6. 위치 권한을 거부했거나 위치를 얻지 못해도 검색과 데모 지점으로 나머지 기능을 그대로 쓸 수 있다.
7. 사용하는 모든 API 키와 설정(카카오, 기상청, Bedrock 리전·모델·가드레일)은 .env 파일로 관리한다. 서버는 backend/.env(항목은 backend/.env.example), 로컬 스크립트는 프로젝트 루트의 .env(.env.example)를 읽고, .env는 저장소와 배포물에 넣지 않는다. AWS 인증은 키 없이 서버의 EC2 IAM 역할을 쓴다.

### 요구사항 8. AI 회피 경로 설명

**사용자 스토리:** 운전자로서 추천 경로가 왜 골라졌는지 숫자 목록 대신 짧은 문장으로 알고 싶다.

**역할 분담**

| 할 일 | 담당 |
| --- | --- |
| 후보 경로 받기, 위험 노출 계산, 추천 경로 선택 | 경로 선택 로직 (코드) |
| 소요시간 차이, 지나는 위험 구간 수 계산 | 경로 선택 로직 (코드) |
| 선택 이유를 문장으로 설명 | LLM (Amazon Bedrock) |

**수용 기준**

1. 경로 결과가 화면에 나온 뒤 화면이 설명 API를 따로 호출한다. 경로 결과는 LLM 응답을 기다리지 않는다. 설명은 경로 결과 카드 아래에 붙인다.
2. LLM에는 계산이 끝난 사실만 넘긴다: 모드(호우경보·호우주의보·강수 단계), 추천 경로와 일반 경로의 소요시간(분), 위험 구간 수와 목록(종류, 이름, 근거, 길이), 추가 소요시간(분), 대체 계산 여부. 좌표는 넘기지 않는다. 구역 이름과 근거는 서버의 위험 구역 데이터에서 가져온다. 알고리즘에 회피 규칙이 있으면 반드시 피할 구간과 되도록 피할 구간의 수도 넘긴다.
3. 강수 단계 0, baseline, 피해야 할 구역이 없는 경우처럼 고정 문구가 있는 상태(요구사항 6.5)는 LLM을 부르지 않는다.
4. 가드레일:
   - 넘겨받은 값만 쓴다. 숫자도 그대로 옮기고 직접 계산하지 않는다.
   - "안전한 경로", "침수되지 않는" 같은 보장 표현을 쓰지 않는다. "알려진 위험 구간을 피한 경로"라고만 표현한다.
   - 이력 기반이라 지금 침수됐는지는 말하지 않는다.
   - 다른 경로를 추천하거나 운전을 권하지 않는다. 이동 자제 안내는 안전 고지가 맡는다.
   - Bedrock Guardrails(근거 확인, 단어 필터)를 설정하면 함께 적용하고, 서버도 금지 표현과 사실에 없는 숫자를 한 번 더 검사한다.
5. 시간 초과, 가드레일 차단, 검사 실패, 호출 한도 초과, 모의 모드에서는 템플릿 문장으로 대신한다. 예: "일반 경로는 위험 구간 2곳을 지나요. 추천 경로는 5분 더 걸리지만 알려진 위험 구간을 지나지 않아요."
6. 대체 경로 엔진으로 따로 계산한 경우(대체_계산: true)에는 그 사실을 설명에 넣는다. 지금은 대체 엔진이 없어 항상 false다.
7. 같은 출발·도착과 같은 위험 구간 조합이면 설명을 서버 메모리에 캐시해 다시 쓴다. 캐시 키는 좌표가 아니라 사실 묶음이다.
8. 화면은 AI가 쓴 문장이면 "AI 설명", 템플릿이면 "경로 설명"으로 표시한다.

### 요구사항 9. 운행 중 비가 강해질 때 경로 변경 요청

**사용자 스토리:** 운전자로서 운행 중 비가 갑자기 강해지면 남은 길이 괜찮은지 다시 판단받고, 왜 바꾸는지 듣고, 손을 쓰지 않아도 더 나은 경로로 바뀌되 원하면 지금 경로를 유지하고 싶다.

**역할 분담:** 경로 재계산과 변경 제안 여부는 코드가 정한다. LLM은 이미 정해진 변경 요청의 이유만 문장으로 쓴다.

**수용 기준**

1. 운행 중 강수 단계가 오르면 차량의 현재 위치와 진행 방향에서 경로를 다시 계산하고, 지금 경로의 남은 길과 새 단계의 규칙으로 비교한다. 경로를 그린 알고리즘과 관계없이 강수 단계 규칙으로 판단한다. 단계가 내려가면 다시 묻지 않고, 열려 있던 요청은 닫는다.
2. 실제 강수를 쓰는 운행은 2분마다 기상청 값을 다시 읽는다. 시연 강수 버튼을 누르면 그 운행은 시연 값을 따른다.
3. 결과는 세 가지다.
   - `recommend`: 반드시 피할 구간이 줄거나, 같으면서 되도록 피할 구간이 줄고 우회 시간이 그 벌점보다 작다. 변경 요청 카드를 띄운다.
   - `keep`: 남은 길에 새 단계에서 피할 구간이 없다. 알림만 띄운다.
   - `no_better`: 피할 구간이 남았지만 더 나은 경로를 찾지 못했다. 경고만 띄운다.
4. 모든 구역을 피하는 경로가 없으면 요구사항 4.9처럼 반드시 피할 구간을 가장 적게 지나는 경로를 고른다.
5. 변경 요청 카드는 현재 경로와 변경 경로의 구간 수(반드시·되도록·그 밖)와 남은 시간, 변경 이유를 보여주고, 지도에 두 경로를 함께 그린다. `경로 변경`을 누르면 바로 바꾸고, 3초 안에 아무것도 누르지 않으면 자동으로 바꾼다. `현재 경로 유지`를 누르면 바꾸지 않는다.
6. 카드는 계산된 템플릿 문장을 먼저 보여주고 LLM 응답이 오면 바꾼다. 요구사항 8의 가드레일과 대체 규칙을 그대로 따르며, 변경을 명령하는 표현도 막는다. `recommend`가 아니면 LLM을 부르지 않는다. 화면은 AI가 쓴 문장이면 "AI 설명", 템플릿이면 "변경 이유"로 표시한다.
7. 알림과 변경 요약을 음성으로 읽는다. 서버 음성(Supertonic)을 먼저 쓰고, 실패하면 브라우저 음성(`speechSynthesis`, ko-KR)으로 읽는다. 변경 요약은 계산된 수로 만든 짧은 문장이고, 더 긴 변경 이유(AI 문장)는 카드에만 표시한다. 음성은 끌 수 있고, 지원하지 않는 브라우저에서는 화면만 동작한다.
8. 시연 주행은 확인이 끝나고 경로를 바꾸거나 유지할 때까지 멈춘다. 남은 초를 카드에 표시한다. 시연 강수에는 "시연 값 · 실제 기상 아님"을 표시한다. 다시 계산에 실패하면 지금 경로로 계속 안내하고 그 사실을 알린다.
9. 더 나은 경로가 없거나 운전자가 지금 경로를 유지하면, 앞에 피할 구간이 남아 있는 동안 경고를 계속 표시한다. 안내를 끝내면 경로 화면은 처음 출발지에서 운행이 끝난 강수 기준으로 다시 계산한다.

### 요구사항 10. 주차한 차 확인

**사용자 스토리:** 차 주인으로서 주차한 곳의 비가 과거 침수일 수준에 닿기까지 얼마나 남았는지 알고 싶다.

**범위:** 남은 시간을 알리는 것까지다. 주차장 추천과 이동 경로는 넣지 않고, 경로·지도·날씨 카드와 상태를 나누지 않는다. 앱을 닫았을 때의 알림은 넣지 않는다.

**수용 기준**

1. 주차 위치는 검색, 현재 위치, 데모 지점으로 정한다. 브라우저에만 저장하고 서버에 저장하거나 기록하지 않는다.
2. 북구 55구역(2021~2023년 기록)에서 위치를 찾고, 밖이면 서비스의 침수 이력(2025년까지)에서 찾는다. 어디에도 없으면 "기록된 침수 구역 밖"이라고 하고 안전하다고 하지 않는다.
3. 기준은 최근 3시간 30mm 이상, 또는 24시간 90mm 이상이면서 3시간 20mm 이상이다. 상습 구역은 0.8배를 쓴다.
4. 지난 24시간 관측값과 초단기예보를 10분 단위로 나눠 기준에 닿기까지의 시간을 구한다. 예보의 범위 값은 큰 수로 읽는다.
5. 문구는 "기준 도달까지 약 N분", "차를 옮길지 확인하세요"로 쓴다. 침수 시각이나 대피 명령으로 표현하지 않는다.
6. 관측값이 없거나 비어 있는 시간이 3시간을 넘으면 판단하지 않았다고 알리고, 비가 없는 것으로 읽지 않는다. 예보를 못 받으면 그 사실을 함께 표시한다.
7. 화면을 열어 둔 동안 5분마다 다시 확인하고, 단계가 오를 때 음성으로 한 번 읽는다. 음성은 끌 수 있고 다른 음성을 끊지 않는다.
8. 시연은 자료의 예시 강수를 쓰고 "시연 값 · 실제 기상 아님"을 표시하며 저장하지 않는다.

## 시연 확인 기준

- 데모 구간: 광주송정역 → 광주역. 침수 이력 구역을 지난다. 이 구간에 지하차도와 하천변은 없으므로, 그 유형의 회피는 자동 테스트로 확인한다.
- 시나리오 A (강수 단계 변화, 데모 모드): 데모 구간에서 tiered_rain으로 강수량을 0 → 35 → 55 → 75mm로 바꾼다. 단계가 바뀌면 경로를 1회 다시 계산한다. 그 단계에서 피할 구역을 지나지 않으면 경로가 그대로일 수 있다.
  - 0mm: baseline과 같은 경로가 나오고 "현재 강수 단계에서는 피하는 구역이 없습니다"가 표시된다.
  - 35mm: 이 구간의 기본 경로에는 1단계에서 피할 구역이 없어 0mm와 같은 경로가 나오고, 지나는 구역은 "이번 단계에서 피하지 않는 위험 구역"으로 표시된다.
  - 55mm: 되도록 피할 구역을 비용으로 비교해 고른다. 이 구간은 '일부 회피'와 지나는 구역, 모두 피할 때의 추가 시간이 표시된다.
  - 75mm: 침수 이력을 모두 피한 경로가 나오고 baseline 대비 추가 소요시간이 표시된다.
- 시나리오 B (장소 검색): "광주역"을 검색해 목적지로 고르면 경로가 표시된다. 광주 밖 결과는 고를 수 없다. 카카오 키를 빼고 실행하면 안내 문구와 데모 지점 목록으로 같은 흐름이 끝까지 동작한다.
- 시나리오 C (기상청): 데모 모드를 끄면 기상청 강수량, 특보, 기준 시각이 표시되고 그 값으로 경로를 계산한다. 기상청 키를 빼고 실행하면 안내 문구가 뜨고 데모 모드로 계속 동작한다.
- 시나리오 D (회피 불가): 목적지를 위험 구역 안으로 정하면 경고, 이유, 지나는 위험 구역 목록과 함께 그 구역을 가장 적게 지나는 경로가 표시된다.
- 알고리즘 비교: API에서 strategy를 hard_exclude, rerank로 바꿔도 같은 형식의 결과가 나온다. 4개 알고리즘이 같은 형식을 돌려주는지는 가짜 엔진 어댑터로 자동 테스트한다.
- 개발자 도구 네트워크 기록: 좌표와 검색어가 URL 쿼리에 없고, 카카오·기상청 키가 브라우저의 요청과 응답 어디에도 없다.

## 이번에 구현하지 않을 범위

- 주제 가이드의 제외 범위: 실제 재난상황 판정, 대피명령 발령, 긴급구조 접수. 실제 도로 통제와 침수 여부도 판단하지 않는다.
- 실시간 교통, 차선 안내, 단속 카메라, 오프라인 지도, 회원 기능
- 광주광역시 밖의 검색과 경로
- 자동차 외 이동 수단(보행, 자전거, 대중교통)의 경로
- 검색어, 출발지·목적지, 경로의 저장(공통 Record CRUD 미사용)
- 경로 설명(요구사항 8)과 경로 변경 이유(요구사항 9) 밖의 AI 기능
- 앱을 닫은 상태의 위치 추적과 푸시 알림

## 핵심 기능 완료 후 선택 사항

- 내비 안내: 다음 회전 안내, 남은 거리·시간, 한국어 음성 안내(브라우저 Web Speech API), 경로 이탈 시 재탐색.
  - Ferrostar 웹 컴포넌트를 쓰고, 백엔드를 'Valhalla처럼 보이는 프록시'로 만들어 Ferrostar가 재탐색할 때도 선택한 알고리즘을 거치게 한다.
  - Ferrostar 웹 버전이 막히면 MapLibre + watchPosition + 안내 목록으로 직접 만든다. 알고리즘 구조는 그대로 둔다.
  - 안내 중에는 Wake Lock API로 화면 꺼짐을 막는다. 웹은 화면이 켜져 있어야 위치 추적이 유지된다.
- 안내 중 자동 재탐색과 알림: 요구사항 9로 옮겼다. 실제 GPS 위치에서의 재탐색은 아직 선택 사항이다.
- GPS 재생 데모: 정해 둔 경로를 따라 위치를 재생해 실제로 주행하지 않아도 내비 안내를 시연한다.
- 알고리즘 비교 패널(개발자용): 같은 출발지·목적지로 여러 알고리즘의 경로를 지도에 겹쳐 그리고, 소요시간과 위험 노출을 표로 비교한다.
- 평가 스크립트: 광주 안 출발지·목적지 100쌍(od_pairs.csv)을 알고리즘마다 돌려 평균 추가 소요시간, 위험 노출 감소율, 경로 생성 실패율을 CSV로 뽑는다. 발표용 수치로 쓴다.
- 다른 경로 엔진(GraphHopper, OpenRouteService 등)의 어댑터. 대체 계산을 넣으면 요구사항 8.6의 대체_계산 값을 채운다.

## 팀 확정 필요

- 데모 구간: baseline 경로가 세 유형의 위험 구역을 모두 지나는 출발지·목적지 쌍. 회전 제한과 일방통행이 OSM과 맞는지 실제로 주행해서 확인한다.
- 위험 구역 원본 자료의 확보처, 정리 담당자, 마감 시각. 침수흔적도는 지자체마다 공개 범위가 달라 내려받지 못할 수 있다.
- 파라미터 초기값: 유형별 버퍼 반경, λ, 유형별 위험 가중치, 특보 반영 규칙(초안: 호우주의보 최소 1단계, 호우경보 최소 2단계).
- 기상청 조회 기준: 광주 대표 지점 1곳으로 할지, 출발지가 속한 구의 지점을 쓸지. 구별로 하더라도 기상청에는 구의 기준 지점만 보내고 사용자 좌표는 보내지 않는다.
- API 키: 카카오 REST API 키와 공공데이터포털 서비스 키(기상청)의 발급 담당과 서버 보관 위치. 키는 저장소와 배포물에 넣지 않는다.
- Valhalla 제외 다각형 제한 설정값: 하천변 구역은 길어서 기본 제한을 넘을 수 있다.
- 휴대폰 시연: 브라우저 위치 API는 HTTPS나 localhost에서만 동작한다. '현재 위치'는 PC 로컬에서 시연하거나, 출발지를 검색으로 정해 시연한다.
- 내비 안내(선택 사항)를 진행할 경우: Valhalla가 한국어 안내 문구를 지원하는지 먼저 확인한다. 지원하지 않으면 회전 유형 코드를 보고 한국어 문구를 직접 만든다.
